VERA-L и DEAL v1.2: является ли одна грамматика подмножеством другой
====================================================================

Дата: 4 сентября 2026
Источники:
  VERA-L    /home/stanislav/work/vera/veran/VERA-L.md, блок ```gbnf``` (89 строк,
            спецификация v0.3)
  DEAL v1.2 test_stand/grammars/deal-v1.2.gbnf
Инструмент: .deps/llama.cpp/build/bin/test-gbnf-validator через gate.accepts()


ОТВЕТ
-----

Нет. Ни одна грамматика не является подмножеством другой. Они пересекаются,
но у каждой есть конструкции, которых нет у другой.


МЕТОДИКА И ОДНА ОШИБКА, КОТОРУЮ ПРИШЛОСЬ ИСПРАВИТЬ
---------------------------------------------------

Двадцать коротких программ, каждая проверена обеими грамматиками.

Первый прогон проверки был неверен: в выводе валидатора искалась подстрока
"valid according to the grammar", а она входит в сообщение об отказе
"Input string is invalid according to the grammar". Все отказы засчитывались
как приёмы, и получалась ложная картина "обе грамматики принимают всё".

Код стенда этой ошибки не делает: gate.accepts() сверяет полную фразу
"Input string is valid according to the grammar." с точкой. Ошибка была в
одноразовом скрипте. Ниже результат после исправления.

---------

Итого: обе 5, только VERA-L 3, только DEAL 12, ни одна 0.

Дополнительно: грамматика VERA-L принимает 4 из 62 эталонных программ
корпуса стенда, написанных на DEAL v1.2.


ЧТО ГОВОРИТ КОМПИЛЯТОР
----------------------

Три конструкции, которые есть только у VERA-L, текущий компилятор DEAL
(коммит 73b93e6) не принимает:

  @jsonable как аннотация     E1001  Unrecognized character: '@'
  постфиксный !               E1037  Expected expression
  функциональный тип          E1032

DEAL записывает директиву комментарием: // @jsonable на отдельной строке.


ПОЧЕМУ В СПИСКЕ "ТОЛЬКО DEAL" ОКАЗАЛИСЬ IMPORT, FOR-OF И WHILE
---------------------------------------------------------------

Эти конструкции в VERA-L очевидно есть. Отвергается не язык, а конкретная
запись правил:

  import ::= "import" ws "*" ws "as" gap identifier gap "from" gap path
    Точки с запятой в правиле нет. `import * as math from "std/math";`
    отвергается; та же строка без точки с запятой принимается.

  for-of-statement ::= "for" gap "(" ws "let" gap identifier ":" type gap
                       "of" gap expression ")" ws block
    Требуется пробел перед `of`, но между `:` и типом пробел не предусмотрен.
    `for (let x: int of v)` отвергается.

  block ::= "{" ws (local-declaration | statement)* "}" ws
    Объявление `let` внутри блока идёт отдельной веткой; сочетание объявления
    и цикла в проверочной программе не разобралось.

Это похоже на недоделки записи грамматики, а не на решения о языке. Для
измерения разницы нет: стенд меряет то, что записано в файле грамматики.


ЧТО ЭТО ЗНАЧИТ ДЛЯ СТЕНДА
--------------------------

Подставить VERA-L как --grammar к существующему пресету нельзя: gate
"грамматика принимает эталоны" упадёт на 58 задачах из 62, и это правильное
поведение.

Чтобы измерять VERA-L, нужны две вещи:
  1. компилятор, который её понимает; текущий три конструкции не принимает;
  2. свой набор промптов, где эталоны написаны на VERA-L. Эталон определяет
     знаменатель покрытия и служит оракулом для скрытого теста, поэтому он
     привязан к диалекту.

Стенд это поддерживает по конструкции: prompts, grammar, compiler и модель
меняются независимо. Пресет грамматики-кандидата может объявить, какие атомы
новая версия убрала (removes) и какие тесты компилятора написаны на старом
языке (expects_rejected_fixtures); объявление проверяется в обе стороны.
